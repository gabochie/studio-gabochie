Help & Reference

How to operate the Command Center

● Ready for Testing?

Partially. The UI is fully built — you can open this page locally and navigate all tabs. However, all data shown (dashboard metrics, agents, workflows, queue, runs, submissions) comes from a Cloudflare D1 database via the /api/* endpoints. Those only work when deployed to Cloudflare Pages with a bound D1 database.

What works offline: tab navigation, keyboard shortcuts, modals, forms (they'll error on submit), settings token storage, help page.

What needs deployment: dashboard numbers, agent list, workflow CRUD, queue processing, run history, preferences/audit, contact submissions, live architecture diagram.

Deploy to Cloudflare Pages with D1 binding, then open https://yourdomain.com/admin/agents.html.

● Getting Started

  1. Admin Key: On first API call you'll be prompted for an admin key. This is stored in your browser (localStorage) and sent as X-Admin-Key on every request. Set or clear it in Settings tab.
  2. Keyboard: Press 1-9 to switch tabs, R to refresh current tab, ESC to close modals.
  3. Mobile: Use the hamburger icon (☰) in the top-left to open the navigation sidebar. Tap outside to close it.

● Tab Reference

1 DashboardReal-time metrics: active agents, queue depth, run counts, error rate, revenue. Activity sparklines show 7-day trends. Agent registry table lists all registered agents with status dots.
2 AgentsManage your agent fleet. Spawn new agents by type (content, outreach, analytics, survey, task_processor). Each agent has a health dot: green=idle, gold=busy, red=error, dim=offline. Kill (deactivates) or Restart agents from the list.
3 WorkflowsAutomated pipelines. Create workflows with a name, description, and trigger type (Manual, Scheduled/Cron, Event-driven). Click a workflow to see its steps, add/delete steps, edit metadata, run manually, or delete the workflow. Steps are ordered sequentially.
4 RunsExecution history of all agents and workflows. Filter by status (all/completed/error/running/pending). Click any run row to see details including timestamps, duration, and error messages. Error rate shown on dashboard.
5 QueuePending work items waiting for agent processing. Shows priority, type, status, and age. Click a row for full detail (payload, result, error). Process 10 and Process 1 buttons drain the queue in batches. Auto-drain runs on cron in production.
6 SubmissionsContact form and booking inquiry submissions from the public site. Filter by status (new/read/replied), click to view full message, auto-marks as read. Track response status.
7 SettingsAuth tokens (agent auth token, admin key) stored locally in your browser. System preferences persisted server-side in D1. Audit log of sensitive operations with timestamp and user/action details.
8 HelpThis page — reference documentation for the Command Center.
9 Architecture Live system diagram showing agent lifecycle, queue flow, and real-time status from D1.

● API Endpoints

GET /api/agents/statusAll agents with type, status, last_seen
POST /api/agentsSpawn a new agent (type, name, config)
PUT /api/agents?id=NUpdate agent status (kill, restart)
DELETE /api/agents?id=NRemove an agent instance
GET /api/agents/runs?limit=...Run history with optional status filter
GET /api/agents/queueQueued work items
POST /api/agents/queueAdd item to queue
POST /api/agents/orchestrate?batch=NProcess N items from queue
GET /api/agents/workflowsAll workflows with step counts
POST /api/agents/workflowsCreate a workflow
PUT /api/agents/workflows?id=NUpdate workflow metadata
DELETE /api/agents/workflows?id=NDelete workflow + its steps
GET /api/agents/steps?workflow_id=NSteps for a workflow
POST /api/agents/stepsAdd step to workflow
PUT /api/agents/steps?id=NUpdate a step
DELETE /api/agents/steps?id=NRemove a step
GET /api/agents/activity7-day daily activity aggregates
GET /api/admin/preferencesSystem preferences from D1
PUT /api/admin/preferencesSet a preference (key, value)
GET /api/admin/auditAudit log entries
GET /api/admin/submissionsContact form submissions

● Architecture

The system uses Cloudflare Pages Functions (serverless) with a D1 database (SQLite-compatible). The admin UI is vanilla HTML/CSS/JS — no framework dependencies.

Agent lifecycle: Spawn → Queue → Orchestrate → Run → Complete/Error. Agents process queued work items and record runs in the database.

See the Architecture diagram for a visual overview with live status.

● D1 Database Tables

Created automatically by functions/api/db/setup.js on first request:

agent_instancesAgent fleet — type, status, config, last_seen
agent_typesType registry — name, description, default_config
workflowsWorkflow definitions — name, trigger_type, trigger_config
workflow_stepsIndividual steps within workflows
agent_queuePending work items with priority and status
agent_runsExecution log — status, duration, error, result
tasksAgent tasks — title, status, priority, phase
settingsKey-value preferences
audit_logSensitive operation audit trail
contact_submissionsContact form entries from the public site
